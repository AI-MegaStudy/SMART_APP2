# 260504 앱 코드 흐름 및 주요 코드

## 1. 현재 앱 구조 요약

현재 앱은 Flutter Material 3 기반의 점주용 모바일 UI이다. 진입점은 로그인 화면이며, 로그인 후 `Home` 쉘로 이동한다. `Home`은 하단 탭 3개를 유지한다.

- 메뉴: 운영 업무 전체 리스트와 상세 페이지 이동
- 홈: 대시보드 지표와 긴급 확인 카드
- 내 정보: 점주 정보, 농장 정보, 로그아웃

주요 화면 파일은 `lib/view` 폴더에 `*_page.dart` 형태로 분리되어 있다. 예외적으로 하단 탭 쉘은 `lib/view/home.dart`이다.

## 2. 앱 진입 흐름

### `lib/main.dart`

`main()`에서 `OwnerApp`을 실행한다.

```dart
void main() {
  runApp(const OwnerApp());
}
```

`OwnerApp`은 `MultiProvider`로 `DashboardViewModel`을 등록하고, `MaterialApp`의 첫 화면을 `LoginPage`로 지정한다.

```dart
ChangeNotifierProvider(
  create: (_) => DashboardViewModel(DashboardRepository()),
)
```

```dart
home: const LoginPage(),
```

테마는 `ThemeData`에서 한 번에 관리한다. 주요 색상은 진한 초록, 민트, 웜 옐로, 블루 톤이며 입력창, 버튼, 하단 네비게이션 스타일도 여기서 공통 설정한다.

## 3. 로그인 흐름

### `lib/view/login_page.dart`

`LoginPage`는 이메일/비밀번호 입력 필드를 가진 로그인 화면이다. 현재는 실제 인증 API 없이 버튼 클릭 시 메인 쉘인 `Home`으로 이동한다.

```dart
Navigator.pushReplacement(
  context,
  MaterialPageRoute(builder: (_) => const Home()),
);
```

`pushReplacement`를 사용하므로 로그인 후 뒤로 가기로 로그인 화면에 다시 돌아가지 않는다.

## 4. 하단 탭 쉘

### `lib/view/home.dart`

`Home`은 앱의 메인 쉘이다. `selectedIndex`로 현재 선택된 탭을 관리하고, `NavigationBar`로 탭을 전환한다.

```dart
int selectedIndex = 1;
```

초기값이 `1`이므로 로그인 직후에는 홈 탭인 `DashboardPage`가 먼저 보인다.

현재 탭 구성은 다음과 같다.

```dart
메뉴 -> MenuPage
홈 -> DashboardPage
내 정보 -> ProfilePage
```

탭 이동은 `_selectTab`에서 처리한다.

```dart
void _selectTab(int index) {
  setState(() {
    selectedIndex = index.clamp(0, pages.length - 1).toInt();
  });
}
```

`DashboardPage`는 홈 카드에서 메뉴 탭으로 이동할 수 있도록 `onJump` 콜백을 전달받는다.

## 5. 홈 대시보드 흐름

### `lib/view/dashboard_page.dart`

`DashboardPage`는 `Provider`를 통해 `DashboardViewModel`을 읽는다. 최초 진입 시 `loadDashboard()`를 한 번 실행한다.

```dart
context.read<DashboardViewModel>().loadDashboard();
```

화면에서는 `dashboard` 값이 있으면 해당 값을 사용하고, 없으면 demo fallback 수치를 보여준다.

주요 지표는 다음과 같다.

- 열린 수확 슬롯
- 신규 발주
- 선별 대기
- 배송 준비
- 반품 요청

홈의 프로필 버튼은 `widget.onJump(2)`를 호출해 `내 정보` 탭으로 이동한다. 지표 카드들은 `widget.onJump(0)`을 호출해 `메뉴` 탭으로 이동한다.

## 6. 메뉴 및 상세 페이지 흐름

### `lib/view/menu_page.dart`

`MenuPage`는 점주 업무를 리스트 형태로 묶어 보여준다. 각 항목은 `MenuEntry`로 정의되며, 탭하면 `Navigator.push`로 상세 페이지를 연다.

```dart
Navigator.of(context).push(
  MaterialPageRoute(builder: (_) => entry.page),
);
```

현재 메뉴 구성은 다음과 같다.

| 섹션 | 페이지 |
| --- | --- |
| 기본 관리 | 상품 관리, 수확 예측 · 슬롯 확정 |
| 주문 처리 | 예약 · 주문 현황, 발주 승인, 신선도 검사 |
| 배송 · 반품 | 배송 관리, 반품 · 환불 관리 |

상세 페이지 파일은 다음과 같다.

- `product_page.dart`: 상품 등록, 포장 단위, 가격 관리
- `harvest_slot_page.dart`: 수확 예측과 슬롯 확정
- `orders_page.dart`: 예약 및 주문 상태 확인
- `procurement_page.dart`: 발주 승인/거절
- `quality_page.dart`: 신선도 검사와 판정
- `shipment_page.dart`: 택배사, 송장, 발송 수량 등록
- `return_page.dart`: 반품 및 환불 관리

## 7. 내 정보 흐름

### `lib/view/profile_page.dart`

`ProfilePage`는 점주/농장 정보를 리스트로 보여준다.

- 내 정보: `OwnerDetailPage`로 이동
- 농장 정보: `FarmDetailPage`로 이동
- 로그아웃: `LoginPage`로 이동하고 이전 라우트 스택 제거

로그아웃은 다음 방식으로 처리한다.

```dart
Navigator.of(context).pushAndRemoveUntil(
  MaterialPageRoute(builder: (_) => const LoginPage()),
  (route) => false,
);
```

이 방식은 로그아웃 후 뒤로 가기로 메인 화면에 돌아가지 못하게 한다.

## 8. 데이터 계층 흐름

현재 대시보드 데이터 흐름은 다음 순서이다.

```text
DashboardPage
  -> DashboardViewModel
  -> DashboardRepository
  -> ApiService
  -> DashboardModel
```

### `lib/vm/dashboard_viewmodel.dart`

`DashboardViewModel`은 `ChangeNotifier`를 상속한다. 로딩 상태, 에러 메시지, 대시보드 모델을 관리한다.

```dart
bool isLoading = false;
String? errorMessage;
DashboardModel? dashboard;
```

`loadDashboard()`는 중복 호출을 막고, repository에서 데이터를 가져온 뒤 `notifyListeners()`로 UI 갱신을 알린다.

### `lib/repositories/dashboard_repository.dart`

`DashboardRepository`는 `/owner/dashboard` API 호출을 시도한다. 실패하면 `DashboardModel.demo()`를 반환한다.

```dart
try {
  final data = await ApiService.get('/owner/dashboard');
  return DashboardModel.fromJson(data);
} catch (_) {
  return DashboardModel.demo();
}
```

현재 프론트엔드는 API 실패 상황에서도 demo 데이터로 화면이 유지되도록 구성되어 있다.

### `lib/model/dashboard_model.dart`

`DashboardModel`은 홈 대시보드 지표 값을 담는다.

- `openSlots`
- `newProcurements`
- `inspectionWaiting`
- `readyToShip`
- `returnRequests`

`fromJson`에서는 `int`, `num`, `String`을 모두 안전하게 정수로 변환한다.

## 9. 공통 UI 코드

### `lib/widgets/owner_widgets.dart`

앱 대부분의 화면은 아래 공통 위젯을 조합해 구성한다.

- `AppScaffold`: SafeArea, 상단 타이틀, optional leading/trailing, 스크롤 리스트 레이아웃
- `HeroPanel`: 초록 배너형 주요 정보 카드
- `GridCards`: 반응형 2열/4열 지표 카드 그리드
- `MetricCard`: 홈 대시보드 숫자 지표 카드
- `DataTile`: 아이콘, 제목, 설명, 상태 배지를 가진 리스트 카드
- `StatusBadge`: 상태 표시 배지
- `SectionHeader`: 섹션 제목과 보조 액션 텍스트
- `LabeledField`, `LabeledBox`: 수정 화면 입력 필드
- `NoticeBox`: 안내 문구 박스
- `ChipRow`: 가로 스크롤 선택 칩
- `ActionChipIcon`: 상단 아이콘 버튼
- `PrimaryAction`, `DualActionBar`: 주요 액션 버튼
- `YieldChart`: 수확량 차트형 UI
- `CameraPreviewCard`: 신선도 검사 촬영 프리뷰 UI

대부분의 페이지는 `Scaffold` 또는 `AppScaffold`를 기본 골격으로 사용하고, 카드/입력/액션 버튼을 children에 넣는 방식으로 작성되어 있다.

### `lib/util/app_colors.dart`

색상 상수는 `AppColors`에 모아져 있다.

```dart
green, mint, line, yellow, blue, text, muted
```

화면 단위에서 직접 색상 값을 흩뿌리기보다 `AppColors`를 사용해 디자인 톤을 유지한다.

## 10. 현재 코드 작성 규칙

- 화면 파일은 `lib/view/*_page.dart`로 작성한다.
- 하단 탭 쉘만 `lib/view/home.dart`를 사용한다.
- 공통 UI는 `lib/widgets/owner_widgets.dart`에 추가한다.
- 색상은 `lib/util/app_colors.dart`를 우선 사용한다.
- 화면 전환은 단순 상세 진입이면 `Navigator.push`, 로그인/로그아웃처럼 스택을 바꿔야 하면 `pushReplacement` 또는 `pushAndRemoveUntil`을 사용한다.
- 대시보드처럼 상태가 필요한 데이터는 `ViewModel -> Repository -> Model` 흐름을 유지한다.
